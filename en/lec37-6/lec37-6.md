## Динамическое программирование и задача о рюкзаке 0/1


## 1. Последовательность решений и состояние задачи


### Условие

Как и в жадном методе (greedy method), решение задачи в динамическом программировании (dynamic programming) рассматривается как результат последовательности шагов или решений. Однако, в отличие от жадного метода, здесь решения не принимаются окончательно и бесповоротно на каждом шаге. 

**Состояние задачи (Problem State):**

Состояние задачи о рюкзаке 0/1 определяется весами и ценностями доступных предметов, а также текущей вместимостью рюкзака. Когда принимается решение относительно очередного предмета (выбирать его или нет), состояние задачи меняется: 

- Предмет больше не доступен для выбора.
- Оставшаяся вместимость рюкзака уменьшается (если предмет был взят).

Если решения принимаются по порядку от 1 до \(n\), то начальное состояние описывается парой \((1, c)\), где доступны предметы с 1 по \(n\), а вместимость равна \(c\). После решения по первому предмету состояние переходит в: 

- \((2, c)\), если мы решили не брать предмет (\(x_1 = 0\)).
- \((2, c - w_1)\), если мы решили взять предмет (\(x_1 = 1\)).


### Решение

Принцип динамического программирования заключается в том, чтобы разбить задачу на подзадачи и сохранять результаты их решений, избегая повторных вычислений. Ниже показано, как меняются состояния рюкзака при обходе предметов. 
```python
def trace_knapsack_states(weights, profits, capacity):
    # Демонстрация переходов состояний для первых двух предметов
    print(f"Начальное состояние: (Предмет 1, Вместимость {capacity})")
    
    # Решение по 1-му предмету
    w1, p1 = weights[0], profits[0]
    print(f"  Выбор x1=0 -> Состояние: (Предмет 2, Вместимость {capacity})")
    if capacity >= w1:
        print(f"  Выбор x1=1 -> Состояние: (Предмет 2, Вместимость {capacity - w1}), Получено ценности: {p1}")
        
# Пример данных: веса и ценности предметов
item_weights = [2, 3, 4]
item_profits = [10, 20, 30]
initial_capacity = 7

trace_knapsack_states(item_weights, item_profits, initial_capacity)
```

## 2. Математическая формулировка задачи о рюкзаке 0/1


### Условие

Пусть \(x_i = 1\), если предмет \(i\) выбран, и \(x_i = 0\), если предмет \(i\) не выбран.
Задача формулируется следующим образом: \[\text{Максимизировать\ }\sum _{i=1}^{n}p_{i}x_{i}\]


при условиях:
\[\sum _{i=1}^{n}w_{i}x_{i}\le c\quad \text{и}\quad x_{i}\in \{0,1\}\text{\ для\ всех\ }i\]

Все ценности (\(p_{i}\)) и веса (\(w_{i}\)) являются строго положительными числами. Решения \(x_{i}\) могут приниматься в любом порядке: от \(1\) до \(n\), от \(n\) до \(1\), или вперемешку. 
### Решение

Для решения этой задачи методом динамического программирования создается таблица (матрица) \(DP\) размера \((n+1) \times (c+1)\), где элемент \(DP[i][w]\) хранит максимальную ценность, которую можно получить, используя первые \(i\) предметов при ограничении по весу \(w\). 
```python
def knapsack_01_matrix(weights, profits, capacity):
    n = len(weights)
    # Создаем DP-таблицу, заполненную нулями
    dp = [[0] * (capacity + 1) for _ in range(n + 1)]
    
    # Заполняем таблицу по состояниям
    for i in range(1, n + 1):
        for w in range(1, capacity + 1):
            # Если текущий предмет весит больше, чем текущая вместимость рюкзака
            if weights[i-1] > w:
                dp[i][w] = dp[i-1][w]
            else:
                # Выбираем максимум между: не брать предмет или взять предмет
                dont_take = dp[i-1][w]
                take = dp[i-1][w - weights[i-1]] + profits[i-1]
                dp[i][w] = max(dont_take, take)
                
    return dp[n][capacity], dp

# Тестовые данные
weights = [2, 3, 4]
profits = [10, 20, 30]
cap = 5

max_profit, table = knapsack_01_matrix(weights, profits, cap)
print(f"Максимальная ценность в рюкзаке: {max_profit}")
```

### 3. Принцип оптимальности (Principle of Optimality)


### Условие

Оптимальное решение обладает следующим свойством:
Каким бы ни было первоначальное решение, оставшиеся решения должны быть оптимальными относительно состояния, возникшего в результате этого первого решения. Динамическое программирование может быть использовано **только тогда**, когда выполняется данный принцип оптимальности. Если выбор первого элемента ломает оптимальность последующей подструктуры (подзадачи становятся зависимыми нелинейным образом), данный метод применять нельзя. 
### Решение

Благодаря принципу оптимальности, мы можем не только найти максимальную стоимость, но и восстановить сам набор предметов (решений \(x_{i}\)), двигаясь в обратном направлении от финального оптимального состояния к начальному. 
```python
def recover_items(dp_table, weights, profits, capacity):
    # Восстановление набора предметов (переменных x_i) из DP-таблицы
    n = len(weights)
    w = capacity
    chosen_items = []
    
    # Идем в обратном порядке от состояния (n, capacity)
    for i in range(n, 0, -1):
        # Если значение изменилось, значит предмет i-1 был выбран
        if dp_table[i][w] != dp_table[i-1][w]:
            chosen_items.append(i - 1) # Сохраняем индекс предмета
            w -= weights[i-1] # Уменьшаем доступную вместимость
            
    # Разворачиваем список, чтобы получить правильный хронологический порядок
    chosen_items.reverse()
    
    # Формируем бинарный вектор решений x
    x_vectors = [1 if i in chosen_items else 0 for i in range(n)]
    return x_vectors

# Используем таблицу из предыдущего шага
x_solution = recover_items(table, weights, profits, cap)
print(f"Вектор оптимальных решений X: {x_solution}")
for idx, chosen in enumerate(x_solution):
    if chosen == 1:
        print(f" -> Выбран предмет {idx} (Вес: {weights[idx]}, Ценность: {profits[idx]})")
```
 

### Доказательство принципа оптимальности и рекуррентное соотношение рюкзака 0/1


## 1. Доказательство принципа оптимальности методом от противного


### Условие

Предположим, что решения принимаются по порядку от первого предмета к последнему: \(X_1, X_2, \dots, X_n\). Пусть последовательность \(x_1 = a_1, x_2 = a_2, \dots, X_n = a_n\) является оптимальным решением исходной задачи.

- **Случай 1:** Если \(a_1 = 0\), то после принятия решения состояние системы переходит в \((2, c)\). Из принципа оптимальности следует, что хвост решения \(a_2, a_3, \dots, a_n\) обязан быть оптимальным решением для подзадачи из состояния \((2, c)\).
    - *Доказательство:* Если бы существовало лучшее альтернативное решение \(b_2, b_3, \dots, b_n\), дающее большую прибыль (\(\sum_{i=2}^{n} p_i b_i > \sum_{i=2}^{n} p_i a_i\)), то объединив его с первым шагом, мы получили бы решение \(X_1 = a_1, X_2 = b_2, \dots, X_n = b_n\), которое имеет общую ценность выше исходной. Это противоречит нашему предположению об оптимальности исходного вектора \(a\).
- **Случай 2:** Если \(a_1 = 1\), то состояние переходит в \((2, c - w_1)\). Аналогично, оставшийся хвост должен максимизировать прибыль для рюкзака вместимостью \((c - w_1)\). Если бы существовало решение \(b\), дающее большую сумму, то исходное решение \(a\) не было бы глобально оптимальным, что ведет к математическому противоречию.

Следовательно, для задачи о рюкзаке 0/1 принцип оптимальности строго выполняется, и метод динамического программирования применим. 

### Решение

Доказательство через противоречие гарантирует корректность восходящего или нисходящего разбора подзадач. Напишем функцию, которая проверяет подструктуру глобально оптимального решения задачи. 
```python
def verify_optimality_principle():
    # Демонстрационный пример для верификации свойства оптимальности подзадач
    profits = [10, 20, 30]
    weights = [1, 2, 3]
    capacity = 5
    
    # Предположим, мы знаем глобальный оптимум: берем предметы 1 и 2 (индексы 1 и 2)
    # Глобальный вектор решений X =, общая ценность = 50, вес = 5
    global_x = [0, 1, 1]
    
    # Шаг 1: Первое решение x[0] = a[0] = 0. Переходим к состоянию (индекс 1, вместимость 5)
    remaining_capacity = capacity - (weights[0] * global_x[0])
    
    # Считаем остаточную ценность хвоста
    tail_profit = sum(p * x for p, x in zip(profits[1:], global_x[1:]))
    
    print(f"Первое решение x_0 = 0. Новое состояние подзадачи: (Предмет 1, Вместимость {remaining_capacity})")
    print(f"Ценность, приносимая оставшимся хвостом решения: {tail_profit}")
    
    # Если бы для рюкзака размера 5 из оставшихся предметов [20, 30] существовало 
    # решение лучше, чем 50, то глобальный оптимум разрушился бы.
    return True

verify_optimality_principle()
```

### 2. Математическое рекуррентное соотношение (Recurrence)


### Условие

Пусть \(f(i, y)\) — это максимальная ценность оптимального решения для подзадачи рюкзака, определяемой состоянием \((i, y)\), где доступны предметы от \(i\) до \(n\), а текущая свободная вместимость равна \(y\). Наша цель — вычислить значение верхнего уровня \(f(1, c)\). 

- **Базовый случай (для последнего предмета \(n\)):** Если оставшийся предмет помещается в рюкзак (\(w_n \le y\)), его выгодно взять, и прибыль равна \(p_{n}\). Если предмет не помещается (\(w_n > y\)), мы не можем его взять, и прибыль равна \(0\): \[f(n,y)=\begin{cases}p_{n},&\text{если\ }w_{n}\le y\\ 0,&\text{если\ }w_{n}>y\end{cases}\]
- **Шаг рекурсии (для любого \(i < n\)):** На основе принципа оптимальности у нас есть ровно два альтернативных пути для принятия решения по предмету \(i\):
    - Не брать предмет (\(X_i = 0\)): состояние переходит в \(f(i+1, y)\). 
    - Взять предмет (\(X_i = 1\)), если позволяет вес (\(y \ge w_i\)): получаем ценность \(p_{i}\), а состояние переходит в \(f(i+1, y - w_i) + p_i\).  Объединяя оба исхода, получаем итоговое рекуррентное соотношение: \[f(i,y)=f(i+1,y)\quad \text{при\ }y<w_{i}\]   \[f(i,y)=\max \{f(i+1,y),f(i+1,y-w_{i})+p_{i}\}\quad \text{при\ }y\ge w_{i}\]


### Решение

Построим рекурсивную древовидную модель вычислений, которая строго следует выведенному математическому соотношению динамического программирования сверху вниз.

```python
def knapsack_recurrence_val(i, y, w, p, n):
    # Базовый случай: дошли до последнего предмета n (в коде Python это индекс n-1)
    if i == n - 1:
        return p[n-1] if y >= w[n-1] else 0
        
    # Если текущий предмет не помещается, пропускаем его
    if y < w[i]:
        return knapsack_recurrence_val(i + 1, y, w, p, n)
        
    # Иначе выбираем максимум: пропустить или взять
    dont_take = knapsack_recurrence_val(i + 1, y, w, p, n)
    take = knapsack_recurrence_val(i + 1, y - w[i], w, p, n) + p[i]
    
    return max(dont_take, take)

# Тестовый пример
item_weights = [1, 2, 3]
item_profits = [10, 20, 30]
knapsack_cap = 5
num_items = len(item_weights)

# Запускаем от начального состояния f(0, c)
result = knapsack_recurrence_val(0, knapsack_cap, item_weights, item_profits, num_items)
print(f"Максимальная ценность рюкзака по формуле f(1, c): {result}")
```

### 3. Реализация рекурсивного кода (Recursive Code)

Для эффективного выполнения рекурсивного кода «сверху вниз» в Python рекомендуется использовать встроенный декоратор кэширования `lru_cache` из модуля `functools` (метод мемоизации). Без кэширования чистая рекурсия будет выполнять экспоненциальное количество повторных вычислений пересекающихся состояний, в то время как кэш снижает временную сложность до полиномиальной — \(\mathcal{O}(n \cdot c)\). 

```python
from functools import lru_cache

# Инициализируем глобальные параметры задачи, как в структуре оригинального кода
w = [2, 3, 4]  # Веса предметов
p = [4, 5, 6]  # Ценности предметов
n = len(w) - 1 # Индекс последнего элемента (для соответствия логике i == n)

@lru_cache(maxsize=None)
def f_recursive(i, y):
    # Базовый тупиковый случай для последнего элемента
    if i == n:
        return 0 if y < w[n] else p[n]
        
    # Предмет слишком тяжелый для текущего состояния вместимости y
    if y < w[i]:
        return f_recursive(i + 1, y)
        
    # Выбор оптимальной ветки по принципу Беллона-Оптимальности
    dont_take = f_recursive(i + 1, y)
    take = f_recursive(i + 1, y - w[i]) + p[i]
    
    return max(dont_take, take)

# Пример вызова для рюкзака вместимостью 5
max_capacity = 5
optimal_profit = f_recursive(0, max_capacity)
print(f"Результат выполнения рекурсивного алгоритма с мемоизацией: {optimal_profit}")
print(f"Статистика вызовов кэша памяти: {f_recursive.cache_info()}")
```


## Временная сложность и мемоизация в задаче о рюкзаке 0/1


### 1. Временная сложность чистой рекурсии


### Условие

Решение рекуррентных соотношений динамического программирования через чистую рекурсию может быть крайне опасным для времени работы программы. 

Пусть t(n) — время, необходимое для решения задачи при наличии n предметов. 

- t(0) = t(1) = a, где a — константа.
- При n > 1 временная сложность составляет t(n) ≤ 2t(n - 1) + b, где b — константа.

В результате раскрытия этого соотношения мы получаем экспоненциальный рост времени работы: \(t(n) = \mathcal{O}(2^n)\). Каждый уровень i дерева рекурсии содержит до \(2^{i-1}\) узлов. На каждом таком узле вычисляется функция f(i, y). Из-за того, что множество узлов вычисляют одно и то же значение f(i, y), время тратится впустую на дублирующие расчеты. Мы можем сэкономить время, сохраняя уже вычисленные значения f(i, y) в словарь (таблицу), где ключом является пара (i, y). Рекурсивный расчет будет запускаться только тогда, когда ключа (i, y) еще нет в словаре. 

### Решение

Покажем на примере счетчика вызовов в Python, как лавинообразно растет количество повторных расчетов в чистой рекурсии без мемоизации при увеличении числа предметов. 

```python
call_counter = 0

def knapsack_pure_recursive(i, y, w, p, n):
    global call_counter
    call_counter += 1 # Фиксируем каждый вызов функции
    
    if i == n - 1:
        return p[n-1] if y >= w[n-1] else 0
    if y < w[i]:
        return knapsack_pure_recursive(i + 1, y, w, p, n)
        
    dont_take = knapsack_pure_recursive(i + 1, y, w, p, n)
    take = knapsack_pure_recursive(i + 1, y - w[i], w, p, n) + p[i]
    return max(dont_take, take)

# Тестовые данные для 5 предметов
weights = [1, 2, 3, 2, 1]
profits = [10, 20, 30, 20, 10]
capacity = 5

call_counter = 0
knapsack_pure_recursive(0, capacity, weights, profits, len(weights))
print(f"Количество вызовов для 5 предметов БЕЗ мемоизации: {call_counter}")
```

## 2. Мемоизация для целочисленных весов через словарь/массив


### Условие

Предположим, что каждый вес и общая вместимость рюкзака c являются целыми числами. В этом случае интерес представляют только такие значения f(i, y), где 1 ≤ i ≤ n и 0 ≤ y ≤ c. Несмотря на то, что уровень i дерева рекурсии содержит до \(2^{i-1}\) узлов, среди них существует не более c + 1 уникальных состояний f(i, y). В качестве словаря можно использовать двумерный массив `fArray` размера `[1:n][0:c]`. Ячейка `fArray[i][y] = -1` тогда и только тогда, когда значение для состояния (i, y) еще не было вычислено. Инициализация этого массива значениями `-1` выполняется до вызова рекурсивного метода и занимает время \(\mathcal{O}(c \cdot n)\).

### Решение

Реализуем создание и предобработку такого словаря-матрицы на Python для последующего эффективного поиска подзадач. 
```python
def init_dict_matrix(n, capacity):
    # Создаем таблицу fArray размера n x (capacity + 1), заполненную -1
    # Каждая строка соответствует предмету, каждый столбец - текущему весу y
    f_array = [[-1] * (capacity + 1) for _ in range(n)]
    return f_array

# Пример инициализации таблицы для 4 предметов и вместимости 10
items_count = 4
cap = 10
fArray = init_dict_matrix(items_count, cap)

print(f"Размер созданной таблицы мемоизации: {len(fArray)}x{len(fArray[0])}")
print("Начальное состояние строки 0:", fArray[0])
```

### 3. Реализация рекурсивного кода без повторных вычислений


Чтобы защитить алгоритм от повторных вычислений (мемоизация), в коде критически необходимы **три вещи**. Без них рекурсивная функция превратится в обычный полный перебор и зависнет на больших данных.

- Наличие структуры данных для кэша (`fArray`).
- Проверка, вычислялось ли это состояние ранее.
- Сохранение нового вычисленного результата в кэш перед его возвратом.

 
```python
# Глобальные параметры задачи, соответствующие структуре исходного кода
w = [2, 3, 4]  # Веса предметов
p = [10, 20, 30]  # Ценности предметов
n = len(w) - 1  # Индекс последнего элемента

# Инициализируем массив fArray значениями -1
# Размерность: (n + 1) строк для соответствия индексам до n включительно
max_c = 5
fArray = [[-1] * (max_c + 1) for _ in range(n + 1)]

def f_no_recomputation(i, y):
    # Если значение уже вычислено ранее, мгновенно возвращаем его из кэша
    if fArray[i][y] >= 0:
        return fArray[i][y]
        
    # Базовый случай для последнего элемента
    if i == n:
        fArray[i][y] = 0 if y < w[n] else p[n]
        return fArray[i][y]
        
    # Если предмет слишком тяжелый, пропускаем его
    if y < w[i]:
        fArray[i][y] = f_no_recomputation(i + 1, y)
    else:
        # Иначе выбираем максимум и сохраняем в таблицу
        dont_take = f_no_recomputation(i + 1, y)
        take = f_no_recomputation(i + 1, y - w[i]) + p[i]
        fArray[i][y] = max(dont_take, take)
        
    return fArray[i][y]

# Вызов для вместимости 5
result_profit = f_no_recomputation(0, max_c)
print(f"Оптимальная ценность: {result_profit}")
print("Итоговое состояние строки кэша 0:", fArray[0])
```

### 4. Сравнение сложностей: Экспонента против Псевдополиномиального времени


### Условие

Благодаря исключению повторных вычислений временная сложность алгоритма сокращается до \(t(n) = \mathcal{O}(c \cdot n)\). Этот подход идеален, когда произведение c ⋅ n мало по сравнению с экспонентой \(2^{n}\). Однако динамическое программирование имеет псевдополиномиальную сложность, и в некоторых пограничных сценариях мемоизация проигрывает чистой рекурсии.
*Рассмотрим пример:* n = 3, вместимость c = 1010101.
Веса предметов: \(w = [100102, 1000321, 6327]\), их ценности: \(p = [102, 505, 5]\). - Число операций чистой рекурсии: \(2^n = 2^3 = 8\).
- Число операций мемоизации (размер таблицы): c ⋅ n = 1010101 × 3 = 3030303. В данном случае инициализация таблицы и поиск в ней будут выполняться в сотни тысяч раз медленнее, чем полный перебор через чистую рекурсию.


### Решение

Покажем на примере вычислений в Python, как в зависимости от соотношения параметров задачи выгоднее выбирать либо табличную мемоизацию, либо полный рекурсивный обход.
 
```python
def compare_complexities(n, c):
    pure_recursive_ops = 2 ** n
    memoization_table_size = c * n
    
    print(f"Параметры задачи: предметов n = {n}, вместимость c = {c}")
    print(f" -> Операций для чистой рекурсии (2^n): {pure_recursive_ops}")
    print(f" -> Размер таблицы для мемоизации (c * n): {memoization_table_size}")
    
    if pure_recursive_ops < memoization_table_size:
        print("Результат: В этой задаче ЧИСТАЯ РЕКУРСИЯ сработает быстрее!")
    else:
        print("Результат: В этой задаче МЕМОИЗАЦИЯ значительно эффективнее!")

# Тест из примера лекции
compare_complexities(n=3, c=1010101)
print("-" * 50)
# Тест для стандартной задачи (много предметов, небольшая вместимость)
compare_complexities(n=25, c=100)
```
